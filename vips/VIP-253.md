## Simple Summary

This VIP proposes a standardized service interface (Generic Delegator) that allows users to delegate transaction gas costs to a third-party gas sponsor, in exchange for a token payment. It aims to simplify integrations for dApps and service providers.

## Abstract

The Generic Delegator abstracts the gas sponsorship process on VeChain by exposing a set of REST API endpoints that any smart contract or service can use to:

- Request gas sponsorship in exchange for payment in VET or other tokens (e.g., B3TR).
- Estimate the gas cost including the sponsorship fee.
- Verify and sign transactions according to the VIP-191 dual-signature format.

This VIP is intended to encourage adoption of the dual-signature pattern introduced in [VIP-191](https://github.com/vechain/VIPs/blob/master/vips/VIP-191.md), making gas delegation safer and more developer-friendly.

## Motivation

Many dApps wish to sponsor gas fees for users or offer users the ability to pay in custom tokens. The Generic Delegator standardizes how to:

- Offload gas costs while maintaining user transaction intent.
- Prevent clause tampering.
- Simplify integration by providing a well-defined API.

## Specification

### REST API

#### `POST /api/v1/sign/transaction/{tokenSymbol}`

Request gas sponsorship for a transaction.

| Field    | Type     | Description                      |
| -------- | -------- | -------------------------------- |
| `raw`    | `string` | Raw unsigned VIP-191 transaction |
| `origin` | `string` | Sender's address (hex format)    |

**Response**

| Field       | Type     | Description                          |
| ----------- | -------- | ------------------------------------ |
| `signature` | `string` | Signature from the sponsor (hex)     |
| `raw`       | `string` | Final transaction body (hex-encoded) |
| `origin`    | `string` | Sender's address (hex format)        |
| `address`   | `string` | Address of the gas payer (sponsor)   |

#### `POST /api/v1/estimate/clauses/{token}`

Estimate the gas cost of a transaction including sponsorship overhead.

The endpoint can support the following query parameters

| Parameter | Type     | Description                                         |
| --------- | -------- | --------------------------------------------------- |
| `type`    | `string` | Target transaction type                             |
| `speed`   | `string` | Transaction speed. Not applicable for 'legacy' type |

and will require to provide the following body

| Field     | Type       | Description                    |
| --------- | ---------- | ------------------------------ |
| `clauses` | `Clause[]` | List of clauses to be included |
| `signer`  | `string`   | Address of the origin          |

**Response**

| Field              | Type     | Description                               |
| ------------------ | -------- | ----------------------------------------- |
| `vthoPerGasAtSpeed`| `number` | gas cost in VTHO at the desired speed     |
| `estimatedGas`     | `number` | Estimated total gas of the new transaction|
| `transactionCost`  | `number` | Transaction cost in the desired token     |
| `serviceFee`       | `number` | Service fee, already included in the cost |

	
### Sanity Check Requirements

Before signing and sending the sponsored transaction, the client MUST:

1. Verify that `chainTag` matches the expected network.
2. Verify the number of clauses is `N+1` (original + payment clause).
3. Ensure the original clauses are untouched.
4. Ensure that the extra clause is for:
   - VET if data is `0x`
   - Token transfer to the expected address if symbol is not VET

### Example: JavaScript Client

```ts
const gasPayerResponse = await callDelegate(rawUnsignedTx, senderAccount.address, "B3TR");
if (gasPayerResponse) {
  const tx_body = decodeRawTx(gasPayerResponse.raw);
  if (runSanityCheck(tx_body, clauses)) {
    const validTx = signVip191Transaction(tx_body, senderAccount.privateKey, gasPayerResponse.signature);
    const txId = await sendTx(validTx);
    const receipt = await getReceipt(txId);
  }
}
```

## Rationale

The dual-signature transaction format (VIP-191) ensures trust and integrity between the sender and the gas sponsor. The sanity checks prevent manipulation of user intent, while the additional clause allows token-based payment to the sponsor.

## Backwards Compatibility

This specification is backward compatible. Transactions follow the VIP-191 format and can be verified by existing clients.

## Security Considerations

- Ensure all sanity checks are enforced before transaction submission.
- Validate the gas sponsor’s address and token logic.
- Always decode and verify the transaction body before signing.
